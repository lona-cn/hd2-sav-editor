# HD2 双甲配置器 (HD2 Armor Desk)

Windows 上的 HELLDIVERS 2 存档双甲配置工具。用 Rust + GPUI 实现，界面全中文，
面向玩家而非逆向工程师：按护甲名称点选，不需要看偏移，也不需要输入十六进制。

- **头部槽位**：从目录里按名字选一件护甲，写进头盔槽位。
- **身体槽位**：默认可直接编辑；需要临时保护原值时可手动锁定。
- **差异预览**：写回前先看清会改哪两个槽位。
- **另存 / 写回**：另存不动源文件；安全与风险写回都会先备份，并在写入后回读核对。
- **单实例运行**：启动时先获取 Windows 命名互斥锁；如果已有实例，新进程提示后退出。

> 这是本机测试通过的可运行程序，不是方案或截图。已知限制见文末「已知问题」。

## 1. 快速开始（不需要 Rust 或 Python）

1. 打开 `target\release\hd2-armor-desk.exe`。
2. 点「打开存档」选择 `.sav`；不确定路径就点「自动查找」。
3. 装备库已内置常用护甲；缺少装备时，点「更多工具 → 导入装备目录」导入 JSON 或 CSV。
4. 在下方列表里找到想要的护甲，点该行的「选择」，它会进入当前选中的槽位。
5. 确认底部差异栏显示的改动，然后：
   - 点「另存副本」：写出一个新文件，源存档完全不动；
   - 点「备份并写回」：在确认框选择安全或风险模式；两者都会备份并回读校验。

首次使用前请退出游戏并手动备份存档；选择装备后先另存副本，再决定是否写回原文件。

### 系统要求

- Windows 10/11 x64。
- 需要 WebView2 以外的系统运行时吗？不需要。程序使用 DirectWrite + Direct3D，
  这些是 Windows 自带组件。
- 不需要安装 Rust、Python 或 .NET。
- 同一 Windows 登录会话只运行一个 Armor Desk 实例，避免重复占用内存和 GPU 资源。

## 2. 界面说明

界面保留深蓝与黄色选中态，移除英文分区标签、编号和常驻操作流程侧栏。
头部与身体的选择、装备库和保存操作位于同一个固定工作区；主界面只滚动装备列表。

### 顶部工具栏

| 按钮 | 作用 |
|---|---|
| 打开存档 | 只读打开本地 `.sav`，不会立刻写入 |
| 自动查找 | 扫描 Steam 存档，列出后由你确认 |
| 预设 | 展开已保存的配装，或保存当前配装 |
| 更多工具 | 展开目录导入、备份恢复、监视、更新和文件信息 |

「只读监视」每 500 ms 在后台读取和校验文件，不占用界面线程，也从不写盘。
「文件信息」集中显示路径、长度、校验值及待写入的字节改动，可直接返回装备库。
「检查更新」下载并校验新版本；没有未保存修改时自动安装并重启。

### 两个槽位卡片

- **头部**：可选择身体护甲或普通头盔；已收录装备显示名称，否则保留未知装备的 ID。
- **身体**：默认可更换护甲；「锁定身体」会放弃尚未写入的身体改动并保留原装备。
  「用作头部装备」可把这件身体护甲用于头部，包括目录未收录的装备。

卡片中的选择按钮决定下方装备列表会修改哪个部位。切换部位时，搜索框同步恢复该部位的搜索词。
装备行保留完整的被动名称和效果；ID 与装备类型移至悬停提示，不再逐行重复显示。

### 底部操作栏

- 左：当前改动摘要。
- 中：「撤销」回退上一步；「另存副本」写入新文件。
- 右：「备份并写回」— 确认后选择安全写回或风险写入最新文件。

## 3. 导入你自己的护甲目录

发布包内置一份由 schema 1 `workspace/catalog.json` 转换得到的 v2 目录，
共 93 个 ID，其中 68 个是身体护甲，67 个已有名称及被动效果。首次启动时会将它写入
`<软件所在目录>\workspace\catalog.v2.json`。如果已存在旧版 v2 目录，只同步匹配 ID 的
已确认类型，并为缺少被动信息的已识别护甲补齐被动名称和效果；玩家已有的名称、备注、收藏及
自定义被动信息都会保留，也不会强制合并其他内置条目。证据分类仅用于程序校验，不在装备库选择列表中显示。

支持三种来源，都不需要手工改列名：

1. **旧 Python 工具的 `catalog.json`**（推荐）：直接选择该文件即可。
   工具的记录形如 `{"offset": 289, "value": 3544585106, "field": "头盔槽", ...}`。
2. **CSV**：支持带 BOM、中文、引号、逗号与换行的字段。
3. **本工具的 v2 JSON**：见 `schemas/equipment_catalog.v2.schema.json`。

导入时如果同一个 ID 出现 hex/decimal 冲突、或同一名字对应不同类型，
工具会列出**具体行号**让你确认，不会静默覆盖你已有的名称和备注。
未知类型的条目会照常显示、可搜索，但普通模式下不会被自动应用。

> 目录文件只是名称对照表。工具不会因为某件护甲「看起来像头盔」就改变它的类型；
> 同名但不同类型的两个物品会作为两条记录保留。

## 4. 写回与备份

写回确认框提供两种模式：

1. **安全写回**：要求磁盘文件仍与草稿基线一致；如果游戏或其他工具已经改过文件，
   就拒绝覆盖。
2. **风险写入最新文件**：重新读取并校验当前磁盘文件，只把用户明确选择的头部/
   身体护甲应用到这份最新内容。游戏刚切换的其他数据会保留；明确选择的护甲槽位
   以本工具为准。
3. 两种模式都会先在 `<软件所在目录>\workspace\backups\` 写入并回读一份独立备份。
4. 只改动白名单范围：头部 `0x121`、身体 `0x129`，以及必须刷新的内层哈希 `0x0C`。
5. 重新压缩变化的 LZ4 块、更新内层 MurmurHash64A 与外层 CRC32。
6. **回读**写出的文件并重新解码，核对目标槽位。

### 恢复

- **恢复普通头盔**：只把头部槽位改回存档里的原值，身体不动。
- **恢复完整备份**：用 `backups\` 里的某份备份整体替换，范围比上面大得多。
  两者在界面上是不同按钮，确认文案也分别写明了各自的影响范围。

### 与游戏同时运行

风险模式允许在游戏刚切换过装备后继续写入，但无法阻止游戏随后再次保存并覆盖结果。
自动监视始终只读。若游戏持续写盘，风险写入仍可能因再次变化而拒绝；等文件稳定后重试。

## 5. 预设

预设只保存「头部用哪件、身体用哪件」这类**装备意图**，不包含存档原始字节、
账号信息或路径。所以：

- 你之后在游戏里换了主武器，再套用旧预设，**武器不会被回滚**。
- 预设引用了目录里不存在的物品时，工具会提示，而不会按相似名字瞎猜。

预设保存在 `<软件所在目录>\workspace\presets.json`。

## 6. 从源码构建

```powershell
cd hd2-armor-desk
cargo build --workspace --release --locked  # 产出主程序与 hd2-armor-desk-updater.exe
cargo test --workspace --locked    # 全部测试
cargo clippy --workspace --all-targets --locked
cargo fmt --check
```

依赖版本固定在 `Cargo.lock`，Rust 工具链固定在 `rust-toolchain.toml`（stable）。
UI 层使用 `gpui-kit 0.6.4`（重导出 GPUI 与组件库），具体版本见 `Cargo.toml`。

### CI 测试配置

CI 使用 `cargo test --workspace --profile ci --locked` 运行全部测试；该配置关闭测试产物及依赖的优化、
调试符号和增量编译，保留开发模式的断言与溢出检查。本地默认 `dev` / `test` 和正式 `release` 优化不变。
下方双向互验命令也使用 `ci` 配置，避免切回默认配置后重复编译。

Windows CI 在独立的 `RUSTUP_HOME` 中按 `rust-toolchain.toml` 安装唯一工具链，再恢复依赖缓存，
避免 runner 预装的其他 Rust 版本改变缓存指纹。测试与发布构建仍并行执行，二者成功后才发布。
GitHub 仍会清理超过 7 天未访问的缓存；长期不提交后的首次运行仍可能需要冷编译。

### 新旧布局与双向互验

支持 `Observed0106`（572088 字节，头部 `060100003eeacea6b8ba0800`）和
`Observed0107`（572092 字节，头部 `07010000b687e357bcba0800`），只接受精确的头部/长度组合。
头部、披风、身体偏移仍为 `0x121`、`0x125`、`0x129`。未知组合只读；编辑不转换布局、不重建尾部。
目录 v2 新增 `secondary_weapon`，最后通牒已分类，副武器仍禁止进入护甲槽。

以下命令从本目录运行；Python 仅用于开发验证，正式程序不依赖 Python：

```powershell
python -m pip install -r ../reference/python/requirements.txt
$env:PYTHONPATH = '../reference/python'
python -m unittest discover -s ../reference/python/tests -v
cargo test --workspace --profile ci --locked
python scripts/oracle_crosscheck.py target/oracle
$env:HD2_REQUIRE_PYTHON_ORACLE = '1'
cargo test -p sav_codec --test oracle --profile ci --locked
Remove-Item Env:HD2_REQUIRE_PYTHON_ORACLE
```

最后一步强制检查两种布局的 Python 输出，缺文件会失败，不会静默跳过。
运行 `python scripts/generate_new_fixture.py` 可重建两份相同的新布局合成夹具及 manifest；
真实玩家存档不作为公开夹具。新一轮验证记录见 `docs/TEST_RECORD.md` 顶部，以下旧记录保留为历史证据。

### 目录结构

```
crates/
  sav_codec/      纯字节层：解压、两层校验、重打包（不含任何 UI 或文件 IO）
  loadout_domain/ 意图与目录：草稿、撤销栈、差异预览、预设、导入
  local_io/       文件事务：稳定读取、只读监视、备份、写回、回读校验
  app/            GPUI 界面与后台任务调度
tests/fixtures/   新旧布局合成样本（不可导入游戏）
examples/         目录与预设的示例文件
```

## 8. 建议的游戏内验收顺序

1. 导入你的真实目录，确认 FS-55 普通头盔与身体护甲是两个不同条目。
2. 打开当前存档，**不做任何编辑**，另存，二进制比较必须完全相同。
3. 游戏运行时开着「只读监视」，正常换一件身体护甲，看卡片是否刷新。
4. 保留备份、退出游戏，用普通头盔做一次对照改档，确认其他配置不变。
5. 再把已验证的 FS-55 身体护甲设为头部，进游戏确认实际槽位，确认没有整体默认化。
6. 试一件你自己新采集的护甲，先确认槽位，再单独测被动效果。
7. 在游戏里换主武器，重新读取后套用旧预设，确认武器没有被回滚。
8. 最后再用长期常用配装做一次完整流程，不要拿唯一可用的存档做破坏性测试。

## 9. 已知问题与边界

- **未知存档布局**：如果文件结构与已验证样本不符，工具会以只读方式打开并
  显示原因，**不允许写回**。这是有意为之，不是 bug。
- **与游戏并发写入仍有竞争**：风险模式会基于最新有效文件重建，但游戏可能在之后再次覆盖结果。
- **不同 LZ4 实现产生的压缩字节可能不同**：这是正常的。验收比较的是解压后的
  语义与未改动块是否复用；只有「无修改另存」才要求整个文件逐字节相同。
- **被动效果倍率、客户端 build 兼容性**：本工具不做任何保证，也没有测量。
- **目录里没有的护甲**：显示为「未知物品 · 0xXXXXXXXX」，这是正常的，
  导入你的完整目录后就会显示名称。
- 测试用的 `.bin` 样本全部是合成数据，**不能导入游戏**。

## 10. 隐私

- 程序不上传存档或其他本机数据，也不扫描整盘；仅在用户点击“检查更新”后访问本项目的
  GitHub Release API，并在用户点击下载后取得发布包。
- 只在软件可执行文件旁的 `workspace\` 目录中读写自己的目录、预设和备份，
  不向 `%LOCALAPPDATA%` 写入文件；更新器不修改 `workspace\`。
- 监视模式只读取你选定的那一个文件。
- 诊断信息只显示路径、长度和校验值，不含存档原始内容。
- 发布包只有在大小与 SHA-256 均匹配 GitHub Release 元数据后才会安装；失败时会尝试回滚，
  若回滚也失败则保留备份与暂存区供恢复。
