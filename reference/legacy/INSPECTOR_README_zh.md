# HD2 SAV Inspector 1.0

一个本地 Python + Tkinter 工具，用于查看 HD2 `testament_new.sav`、监视游戏写盘、采集装备 ID、对照二进制变化以及编辑/保存副本。无需 Electron、浏览器服务或游戏进程注入。程序运行时不联网；首次安装 `lz4` 需要从 Python 包仓库下载依赖。

**本工具不是完整的存档语义解析器，也没有最新的全装备 ID 数据库。它显示实际数值，让你通过游戏内逐项装备确认并命名。**

## 快速启动（Windows）

安装带 Tkinter 的 Python 3.10 或以上，把整个 ZIP 解压到桌面等可写目录，不要放进 Steam `userdata`，也不要只打开 ZIP 内的一个脚本。

首次双击 `INSTALL.cmd`：检查 Python/Tkinter、在工具目录创建 `.venv`、安装唯一的第三方依赖 `lz4==4.4.5`。以后双击 `START.cmd`。

已有 Python 环境也可直接运行：

```powershell
python -m pip install -r requirements.txt
python .\sav_gui.py
```

可指定文件和工作区：

```powershell
python .\sav_gui.py "C:\Program Files (x86)\Steam\userdata\你的账户目录\553850\remote\testament_new.sav" --workspace "D:\HD2-ID-Catalog"
```

可以把 `.sav` 拖到 `START.cmd` 上作为启动参数；程序窗口本身未实现拖放。`python -m tkinter` 可检查 GUI 环境。Linux 可能需要系统的 `python3-tk`；本工具面向 Windows，Linux/Xvfb 仅用于此次离线 GUI 测试。

## 正好适合这次的采集流程

1. 保持游戏运行。工具点“浏览”，选择实际正在更新的 `remote/testament_new.sav`，或者用“查找 Steam”。多个账户会让你选择，不自动猜账户。
2. 保持“自动监视（只读）”勾选，**不要开启编辑**。默认 500 ms 检查一次。切回游戏，只改变一项装备；等工具出现对应的新数值后再切下一个。
3. “装备 / 观察字段”页显示当前 ID、十六进制/十进制、上一份 ID、名称、用途依据。变化行黄色；首次读取的非零观察值以及之后的新值都会加入 ID 表。
4. 双击该行，输入游戏显示的名称，例如 `TG-8 神枪手（身体护甲）`。名称、备注立即保存在 `workspace/catalog.json`，不需要点“保存到源文件”。也可在“已采集 ID”页双击标注。
5. 继续在游戏中切换装备。目录按 **正文偏移 + 数字 ID** 去重；同名头盔和身体护甲不是同一个 ID。打开“已采集 ID”可以过滤、复制 ID、导出 JSON/CSV。

**采集依赖游戏实际写盘，不是读取正在运行游戏的内存。**尚未写入文件的装备、快速被后一次写入覆盖的中间状态不会被保证捕获。不要连续快速点完几十件；确认 ID 已出现再继续。一次改多项也会记录，但名字与字段的对应更难判断。

不保证获取从未正常装备、不可用或尚未解锁的物品 ID；扫描出一个数值也不证明拥有该装备。

## 四个页面

### 装备 / 观察字段

已知布局下预置：头盔槽 `0x0121`、身体护甲槽 `0x0129`、披风槽 `0x0125`。这些是解压正文里的 uint32 little-endian，不是压缩 `.sav` 文件的偏移。

其余字段保留“未知 / 待确认”标记。`0x0011/0x0015/0x0019` 等只是可观察位置，**不擅自标成主武器、副武器或手雷**。战略配备记录的当前用途同样待你确认。预设表不覆盖全部存档。

“新增观察字段”可添加任意合法 uint32 起点；“重命名字段”用于在你实测确认后赋予语义。移除观察字段不删除已经采集的 ID，不改游戏文件。

### 前后差异

比较“上一份有效磁盘快照”或“固定比较基线”。默认范围 `0x10～0x400`，排除头部校验及大量远端统计/文本噪声。可改起止偏移，或选择“查看全文范围”。范围为前闭后开。

每行是连续变化的字节段，并给出在该起点读取的 uint32。**变化段不一定等于字段边界。**若一个四字节 ID 仅一字节改变，变化段可能从字段中间开始；新增观察时需要确认真正的四字节起点。

例如，为定位某种武器字段：设置基线 → 游戏内只换主武器 → 看差异 → 换回原武器复查可逆变化 → 将确认的位置加入观察表。不能仅因某个值随操作变化，就排除它是历史记录或索引副本。

底部事件表显示最近 600 条观察字段事件；完整事件持续追加到 `workspace/observations.jsonl`，不是完整存档快照。全文差异表上限 2000 行，截断时会提示。

### 已采集 ID

自动保存、手动命名/备注、搜索、复制、JSON/CSV 导出。未知数字记录可能包含非装备值，需要你的逐项操作确认。“来源字段”是观察槽位，不保证该值的实际物品类型；头盔槽完全可能出现此前你验证过的身体护甲 ID。

只内置此前已辨认的 FS-55/B-01 少量名称。不含猜测的 TG ID，不在线查询第三方服务。

### 原始正文 / HEX

分页查看全部解压正文，每页 512 字节，支持跳转、uint32 ID 搜索、HEX 字节搜索、UTF-8 文本搜索、正文 `.bin` 导出。搜索到底后从头继续。

默认只读。开启编辑后，可在指定正文偏移暂存一个 uint32；不支持改变文件逻辑长度或直接编辑前 16 字节。未知格式只读，不会强制套用写入偏移。

## 三种不同的“保存”

| 操作 | 保存什么 | 是否写游戏源文件 |
|---|---|---|
| ID 表自动保存 / 导出 JSON、CSV | 数字 ID、你填写的名称、备注、时间等 | 否 |
| 保存当前磁盘快照 | 最近成功读取的完整原始 `.sav`；不含内存编辑 | 否，写一个新文件 |
| 另存 SAV（Ctrl+S） | 基于当前编辑基线、包含暂存修改的新存档 | 否，写一个新文件 |
| 保存到源文件 | 包含编辑的存档，覆盖当前观察路径 | 是，需要明确确认，先备份 |

“另存”保留内存编辑，不自动切换观察目标。副本文件已存在时拒绝覆盖，请选新文件名。这样不能意外用快照或输出副本覆盖正在运行的游戏文件。

**编辑以这次实际打开的文件为基线，不使用以前上传的历史配装。**字段修改先在内存暂存：蓝色表示待保存，黄色表示读取变化。源文件若在此期间被游戏更新，工具保留你的旧编辑但提示冲突，不暗中把新旧两份正文拼接。需要放弃旧编辑后跟随磁盘，或明确另存旧基线副本。

## 写入校验和安全边界

重新保存时自动：

- 对完整逻辑正文（不含块尾填充）计算 MurmurHash64A，seed=0，正文 `0x0C～0x0F` 先置零；低32位回写正文 `0x0C`。
- 仅重新压缩发生变化的 raw LZ4 块；未改块保留原始压缩字节。
- 更新容器长度和 `CRC32(file[0x10:])`，把 CRC 写到压缩文件 `0x0C`。
- 重新解压、同时验证两层校验、逐字节验证目标正文。

没有编辑的另存会保持原始文件逐字节相同。

**游戏运行时采集是只读操作；不要据此认为并发回写也安全。**“暂停监视”只暂停工具读取，不会阻止游戏写文件。

覆盖源文件前，应先停止游戏写入（通常退出游戏），并留意 Steam Cloud。工具会检查源文件 SHA256、生成备份、临时写入，再次检查源文件后替换；但文件检查与替换之间仍可能有竞态，无法替代与游戏协调的文件锁。保存后也不保证运行中的游戏立即重新加载改动。

备份在 `workspace/backups/`。本工具不保证错误字段仍能被游戏接受，不保证第二套被动有效，也不能消除账号风险。

已知结构头部是 `060100003eeacea6b8ba0800`、逻辑长度 572088。外层格式/校验通过但头部不符合时仅允许查看；相同头部也不保证未来客户端字段语义永远不变。没有“自动修复未知版本”的操作。

## 工作区文件与隐私

默认工作区为工具目录下的 `workspace/`：

```text
catalog.json         自动保存的 ID 与名称目录
observations.jsonl   观察字段变化事件；可自行归档，不会自动裁剪
settings.json        文件路径、检查间隔、自定义字段
backups/             只有明确回写源文件时才生成的完整备份
error.log            出错时的本地错误信息
```

未启用自动全存档快照，因此采集不会不停复制 500 KiB 正文。ID表遇到损坏会停止启动并说明原因，不覆盖原表；先备份后自行移走坏表，或使用新工作区。

完整 `.sav/.bin` 可能含账户、会话等信息；本工具不上传。测试/截图用合成数据，分发包不包含你上传的存档或个人 ID 表。

## 快捷键

`Ctrl+O` 打开；`F5` 手动读取；`Ctrl+S` 另存 SAV；`Ctrl+F` 跳转到 ID 表搜索。

## 验证与源码

`sav_gui.py` 是 GUI；`hd2_core.py` 是独立可测试的编解码和数据层；测试均在 `tests/`。

```powershell
python -m unittest discover -s tests -v
```

Windows 可双击 `TEST.cmd`。Linux 无显示环境下 GUI 测试会明确跳过；此次用 Xvfb 实际执行了 GUI 测试，不仅检查 import。

本次验证覆盖双层校验、第一块与后续块修改、部分写入重试、文件冲突、备份、目录去重、脏编辑不被外部刷新覆盖、手动刷新、界面控件可见性。还使用之前两份真实上传样本做了只读解码与重打包差异核验，样本不随包提供。测试数量和结果以 `test_results.txt` 为准。

**未在你的 Windows 机器或正在运行的 HD2 客户端旁完成端到端实测。**Windows 启动脚本已提供，命令语法作了检查，但不声称已经在 Windows 执行。
