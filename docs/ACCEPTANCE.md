# 验收清单与验证记录模板

这是**尚待新Rust应用执行**的验收清单。勾选只能基于具体测试结果，不能把交接包的Python测试代替Rust/Windows验证。

## A. 数据正确性（任何一项失败都不允许回写真实源文件）

- [ ] A01：14个fixture按manifest预期接受/拒绝；unknown-layout不允许写。
- [ ] A02：228组MurmurHash64A向量一致，包含0长度与1..7尾字节。
- [ ] A03：无修改另存与输入raw完全一致。
- [ ] A04：只修改head，body/cape及其他payload数据不变。
- [ ] A05：只修改body，head/cape及其他payload数据不变。
- [ ] A06：同时设head/body，实际变更仅在两槽和内层hash范围内。
- [ ] A07：所有重打包结果两层校验均通过；Rust输出可被Python读取。
- [ ] A08：未变化压缩块保留；后续块改动时检查第0块hash也刷新。
- [ ] A09：错误内层checksum即使外层CRC正确也被拒绝。
- [ ] A10：未知字段原样保留，无全局ID替换、无长度变化、无任意清零。
- [ ] A11：`0x0121`等未对齐offset使用安全小端读取，debug/release结果一致。
- [ ] A12：恶意长度/截断/非零padding/多余尾部不会panic或超量分配。

## B. 目录与预设

- [ ] B01：原Python JSON直接导入，无手工列变换。
- [ ] B02：原CSV含BOM、中文、引号、逗号、换行可导入。
- [ ] B03：hex/decimal冲突报告具体行；非法u32不截断。
- [ ] B04：同名FS-55 Helmet与Armor为两个物品。
- [ ] B05：同一Armor在head/body观察时保留两来源，不变成两个类型。
- [ ] B06：未知类型可見、可查、可人工确认，普通模式不擅自应用。
- [ ] B07：重复导入幂等，已有手工名称/备注不丢，原目录文件未改。
- [ ] B08：JSON schema与运行时语义检查同时存在；key/type/id不一致拒绝。
- [ ] B09：被动/重量/图片缺失仍可用ID；未命名物品不隐藏。
- [ ] B10：预设`Keep`无patch；预设不含raw save、账号或路径。
- [ ] B11：创建预设后更换武器，再应用预设保留最新武器。
- [ ] B12：预设引用未知/冲突物品时不按相似名称自动替换。

## C. 玩家体验

- [ ] C01：主界面有头部/身体双卡片，不以HEX为主操作。
- [ ] C02：头部卡片明确显示物品实际类型，不只显示同名标题。
- [ ] C03：body默认锁定；只换head的路径不超过约4个主要操作。
- [ ] C04：选择、收藏、命名、导入、保存预设都不触碰源文件。
- [ ] C05：搜索支持中文、英文别名、型号、hex和decimal ID。
- [ ] C06：dirty差异显示名称、类型、ID与保持不变项。
- [ ] C07：恢复普通头盔不误用先前Armor头部值。
- [ ] C08：全部主要操作有键盘方式；输入法组合状态不被快捷键破坏。
- [ ] C09：900×620到高DPI下保存/冲突按钮可访问，无裁切陷阱。
- [ ] C10：读文件更新不重建输入状态、不丢焦点或未完成输入。
- [ ] C11：没有图片/metadata/全量catalog时仍可打开主界面与示例。
- [ ] C12：成功文案区分文件保存与游戏被动生效，没有虚假叠加保证。

## D. 监听、冲突与账号路径

- [ ] D01：游戏文件半截更新时保留last-good，完整后才刷新。
- [ ] D02：游戏rename-replace写盘仍可跟随，工具不长期占有源句柄。
- [ ] D03：不同SHA且有dirty时进入Conflict，草稿保留、不自动合并。
- [ ] D04：明确选择“最新基线重新应用意图”后生成新预览和revision。
- [ ] D05：切换文件/账号后，旧generation后台事件被忽略。
- [ ] D06：Steam多账号时用户选择，无自动最新账号猜测。
- [ ] D07：暂停监听不被描述成停止游戏写入。
- [ ] D08：短暂错误不刷屏，持续错误可见，旧快照标记过时。

## E. 文件事务与回滚

- [ ] E01：另存不覆盖已存在目标，不自动把输出改成源。
- [ ] E02：JSON/CSV/BIN导出不可指向源文件同一身份。
- [ ] E03：源revision变化时写回拒绝，最新文件保留。
- [ ] E04：备份创建和SHA验证失败时源不动。
- [ ] E05：临时文件与源同卷，flush/sync后再替换。
- [ ] E06：Windows占用、只读、权限不足、长路径、磁盘满都实测。
- [ ] E07：保存后必须回读；回读被其他写入替换时不提示成功、不抢写。
- [ ] E08：复杂替换失败保留备份/临时现场，不虚称原件未改。
- [ ] E09：同文档只能一个提交，重复点击不能竞态写回。
- [ ] E10：恢复普通头盔与恢复整份备份有不同范围确认。
- [ ] E11：恢复备份前保存当前副本；保留最后可靠备份。
- [ ] E12：游戏运行中默认不自动回写，不替用户退出游戏/改SteamCloud。

## F. Windows交付与隐私

- [ ] F01：Windows release程序在无Python/Rust环境下可运行，实际依赖已说明。
- [ ] F02：Cargo.lock和toolchain固定；没有浮动main/*；真实构建命令有记录。
- [ ] F03：fmt、clippy、测试结果附日志；skip明确区分。
- [ ] F04：中文版README说明导入/另存/回写/恢复/未知版本策略。
- [ ] F05：包内无真实sav、私人catalog、账号/会话信息、系统字体。
- [ ] F06：运行不联网、不上传错误报告、不扫描整盘。
- [ ] F07：日志去敏且轮转；诊断导出默认无raw payload。
- [ ] F08：图片路径验证和压缩包/目录导入不越界、不执行命令。
- [ ] F09：记录启动、RSS、CPU/GPU空闲使用和EXE大小，注明机器。
- [ ] F10：最终截图使用合成数据，不能让截图替代真实可运行程序。

## G. 用户游戏验收（人工，不假造自动通过）

- [ ] G01：普通头盔更换，其他装备/角色不变。
- [ ] G02：已验证的FS-55 Armor进入head，body保持正确。
- [ ] G03：用户全目录中一件新Armor进入head，未整体默认化。
- [ ] G04：游戏内改武器后套用预设，武器不回滚。
- [ ] G05：重启后状态结果记录；换装后是否保留异常head单独记录。
- [ ] G06：被动效果测量单独记录，不从装备名推断；未知继续标未知。
